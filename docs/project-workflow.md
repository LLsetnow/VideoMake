# 项目结构与生成流程

## 项目目录

每次开始新的视频生成项目，先在 `projects/` 下创建一个能看出角色、主题或场景的总文件夹，例如：

```text
projects/千夏_青春的幻象_音乐工作室/
```

单个短视频项目：

```text
projects/<项目名>/
├── <项目名>_workflow_api.json
├── <项目名>_prompt.txt
└── output/
```

长视频按时间序列拆成子项目，每个子项目独立保存工作流、提示词和输出：

```text
projects/<项目名>/
├── 1-15秒/
│   ├── <项目名>_1-15秒_workflow_api.json
│   ├── <项目名>_1-15秒_prompt.txt
│   └── output/
├── 16-30秒/
│   ├── <项目名>_16-30秒_workflow_api.json
│   ├── <项目名>_16-30秒_prompt.txt
│   └── output/
└── ...
```

子项目应可独立提交和复现，提示词和文件名要标明全片时间线位置。起止时间优先落在自然画面切点或鼓点切点，不要为了整齐强制使用固定 15 秒边界。

单个本地工作流时长为 2–15 秒，15 秒不是固定要求；官方在线/API 运行时遵循当前 H3 Skill 的 4–15 秒、24 FPS 和 7000 字符限制。本地运行时有更窄限制时，以本地运行时为准。不能拆出不足 2 秒的尾段，例如 16 秒不要机械拆成 `15+1`。

## 鼓点卡点与工作流分段

- 先用 `opc music beats` 检测鼓点/起音，从较强候选点选择切换点；不要让每个鼓点都强制切镜。镜头切换通常约 2–3 秒一次，弱鼓点用于画面内动作、色块、光线或几何脉冲。
- 工作流段落边界应落在已确认的自然画面切点、鼓点或起音点；不要只按固定 15 秒切段后让画面状态跨段延续。
- H3 单个工作流最长 15 秒；非固定时长时增加工作流数量，且每段都满足本地最小/最大时长。
- 生成前为每段建立全局起止时间、局部切点和源音频区间；锁定源音频时各段 `LoadAudio`/裁切节点必须使用同一时间范围，段落之间不能重复、遗漏或重新生成音乐。
- 不要默认将每个 2–3 秒镜头拆成独立工作流；相邻镜头优先合并到不超过 15 秒的长段，并在提示词中写局部切点。只有段落边界必须落在自然切点时才增加或调整工作流。
- 拼接按 24fps 进行帧级裁切和核验；段落目标帧数由真实时长计算，最终总帧数必须与目标时长一致。
- **做卡点（beat-locked）视频时，先读取 `.codex/skills/beat-locked-redundant-video-edit/SKILL.md`**，按其规范执行：生成视频作为可复用素材池而非唯一剪辑源；切点只选强拍/强起音、间距约 2–3 秒；场景检测结果仅作排除信息并保留 guard band；帧级裁剪后 remux 原始源音频并逐段校验帧数。现成实现参考 `projects/情感失色症_60秒/analysis/detect_generated_assets.py` 与 `build_beat_locked_edit.py`。

## 标准流程

### 1. 初始化

先判断短视频或长视频，建立 `projects/<项目名>/` 及所需子项目；后续本项目的工作流、提示词和输出都放在那里。

### 2. 确定故事和时间线

确定故事目标、角色、场景、片段数量、每段时长、画幅、对白/歌词、音乐和最终顺序。时间应根据分镜、动作节奏和台词长度决定，不为凑满 15 秒而填充。

### 3. 编写镜头脚本

至少明确角色及身份参考、场景与构图、可观察的动作顺序、镜头运动/景别/光线/风格、对白/歌词/环境声/角色声音/非叙事音乐，以及首帧/尾帧/参考图/参考视频/音频的用途。

### 4. 生成静态参考图

使用 `image-gen` 生成参考图，不使用 SVG 等矢量图。人物卡片固定采用整体 `1:1` 栅格画布：左侧约 `2/3` 为正面半身，右上为侧面全身，右下为背面全身；三视图保持发型、服装、配色和身份特征一致。可复用角色图归档到 `character/<角色名>/`，背景图归档到 `background/` 或角色的场景图目录；一次性首帧/尾帧随项目管理。

不要只凭文件名猜用途。接入工作流前确认文件真实存在、格式可读、方向比例正确，并确认它是主体身份、首帧、尾帧、背景、动作参考还是音频参考。

### 5. 生成提示词和工作流

按 [`docs/h3.md`](h3.md) 走 H3 Skill 路由；将确认后的英文提示词和完整中文翻译保存到当前项目或子项目。批量图生视频的父 Agent 指令、四镜模板和单图提示词规范见 [`how-to-write-prompts.md`](how-to-write-prompts.md)。按 [`docs/aigate.md`](aigate.md) 修改并提交 workflow，使用 JSON 校验工具确认格式。

### 6. 生成、剪辑和交付

按 [`docs/aigate.md`](aigate.md) 创建/提交实例，按 [`docs/editing-delivery.md`](editing-delivery.md) 进行帧级剪辑、源音频核验、最终输出归档和 `videoOutput/` 软链接检查。

## 批量单图单视频流程

当一批参考图需要各自生成一个视频时，按“一张图、一个提示词、一个工作流、一个任务、一个输出目录”的边界处理。不要把多张图放进同一个 H3 上下文，也不要用上一个任务残留的输入路径覆盖当前任务。

### 1. 建立批次清单

为整批建立 `projects/<批次名>/batch_manifest.json`，记录批次 ID、工作流模板、默认画幅、分辨率、时长、采样参数和每张图的输入顺序。每张图再建立 `reference/<序号>.png` 与同序号子目录。

单图目录至少包含：

```text
projects/<批次名>/<三位序号>/
├── source.png
├── shots.json
├── prompt_en.txt
├── prompt_zh.txt
├── workflow_api.json
├── task_request.json
├── manifest.json
├── output/
└── qa/
```

### 2. 先完成一张样片

批量首采默认并发为 `1`。先提交第一张图，检查四镜动作、人物连续性、男性脸部是否出画、男性是否静音、女生喘息是否清楚、实际时长和解码结果。样片未通过时先修正提示词或工作流，不把错误配置复制到其余图片。

提示词模板和音画验收要求见 [`how-to-write-prompts.md`](how-to-write-prompts.md)。

### 3. 生成独立任务请求

每张图分别生成任务请求，并明确 `execution_target`。使用 RH 流程时，通过 RH Workflow Desk 本地 Web API 提交，不直接调用 RunningHub 创建任务接口。请求中的本地 `workflow_id`、远程 `remote_workflow_id`、Prompt Group、输入文件和输出目录必须属于当前图片。

### 4. 有界并发

样片通过后可以按账号额度扩大并发，但必须为每个任务保留独立状态。允许并行上传、排队或轮询，不允许并发任务共享同一个可变 workflow 文件、同一提示词文件或同一输出目录。

### 5. 状态恢复

总 manifest 的每图状态至少包含 `pending`、`prepared`、`queued`、`running`、`done`、`failed`。恢复批次时先检查实际文件和任务记录。已完成并通过 QA 的条目跳过，运行中的条目继续轮询，失败条目只重试自身。

### 6. 批量验收

每张完成视频都要检查 MP4 可完整解码、时长、画幅、分辨率、镜头数、人物连续性、动作连续性和音轨。批量结束时报告完成数、失败数、跳过数、成功文件路径、失败阶段、本地 task ID 和远程 task ID。`202` 只表示本地任务入队，不等于视频生成成功。
